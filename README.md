# Classify — доска объявлений в Telegram

Classify — Telegram Mini App с объявлениями для русскоязычных, живущих за рубежом: Бали, Пхукет, Бангкок, Дубай, Тбилиси. Аренда жилья и байков, услуги, вещи, работа — то, что сейчас ищут и предлагают в хаотичных чатах-барахолках.

Главная идея — **локальность**. Город и район — главный фильтр и главный контекст: место выбирается в шапке в один тап, у каждого объявления видно район и расстояние.

> **Статус:** только фронтенд на мок-данных. Бэкенда, авторизации, оплаты и модерации пока нет. Все люди, объявления, отзывы и цифры в `src/mocks` вымышлены.

Продуктовые принципы и аудитория — в [PRODUCT.md](PRODUCT.md), дизайн-система — в [DESIGN.md](DESIGN.md), текущее состояние работ — в [HANDOFF.md](HANDOFF.md).

## Аудитория

Экспаты и долгосрочные путешественники, говорящие по-русски. Открывают приложение на телефоне из Telegram-бота; связь с продавцом — переход в личный чат Telegram. У каждой страны своя валюта: цена объявления пишется в валюте страны, где оно опубликовано (Индонезия — IDR, Таиланд — THB, ОАЭ — AED, Грузия — GEL).

## Функции

### MVP (свёрстано на моках)

- Лента «Рядом с вами» в выбранном городе: сначала выбранный район, затем остальной город; сортировка «Ближе» / «Новые».
- Выбор места: страна → город → район, с поиском и счётчиком объявлений.
- Категории (10 штук) на главной и в поиске.
- Поиск по тексту — только в выбранном районе (без района — весь город), с фильтрами: сортировка, цена (в валюте страны выбранного города), состояние, доставка, только с фото.
- Карточка объявления: галерея, цена, район и расстояние, описание, характеристики, продавец, похожие рядом; «Написать» открывает чат с продавцом в Telegram.
- Подача объявления — мастер из 5 шагов: категория → фото → город и район → описание и цена → проверка. Город выбирается до цены: он определяет валюту. На шаге 4 — необязательные характеристики выбранной категории; заполненные значения видны при проверке и в карточке объявления. После публикации объявление уходит «на проверку».
- Избранное (с бейджем на таб-баре).
- **Уведомления («ищу»)**: человек описывает, что ищет (например, MacBook M2 в Бангкоке до 35 000 ฿), — это не публикуется, но когда появляется подходящее объявление, бот присылает сообщение. Создаются из раздела «Уведомления» (+) или из поиска («Уведомить о новых» / «Уведомить меня» при пустом результате). В разделе видно число новых совпадений, подписку можно поставить на паузу или удалить (изменить нельзя); активных — не больше 5; бейдж на таб-баре — сумма новых совпадений.
- Мои объявления: активные / на проверке / архив; действия «Поднять», «В архив», «Восстановить».
- Профиль продавца с рейтингом и отзывами; мой профиль с настройками.
- **Проверка личности (KYC)**: кнопка в «Мой профиль» → страница `/kyc`. Прошедшим проверку ставим отметку «Личность подтверждена» (галочка у имени) в объявлениях и профиле, не прошедшим — ничего. Провайдер — **Didit** (решено; интеграция — следующий этап, сейчас мок).
- Интеграция с Telegram: `ready/expand`, нативные BackButton и MainButton, haptics, цвета шапки, открытие чата.

### Следующий этап

- Бэкенд на FastAPI + PostgreSQL + Redis (см. «Архитектура») и замена мок-API на `fetch`.
- Авторизация по Telegram `initData` (проверка подписи на сервере).
- Реальная загрузка фото (`<input type="file">`) и хранилище для них.
- Определение места по IP на сервере (во фронте уже есть экран первого запуска и кнопка «Определить автоматически» на моке): определили — показываем город, нет — выбор страны и города.
- Расстояние по геолокации пользователя.
- Уведомления через бота (ответ модерации, снижение цены в избранном).

### Пожелания — **не решено**

Ниже — идеи, по которым решений нет. Ничего из этого не реализовано и не утверждено.

- **Монетизация** — не решено, поставлена задача проработать тарифы, места для платных объявлений и оплату (список вопросов — в HANDOFF.md). Обсуждалось платное поднятие / VIP за Telegram Stars; в интерфейсе есть кнопка «Поднять» и бейдж «Поднято», но оплаты нет.
- **Модерация** — не решено (кто модерирует, сроки, правила, запрещённые категории). Текст «обычно проверяем за 15 минут» — заглушка.
- **Мультиязычность** — на старте только русский, выбора языка в настройках нет (решено). Другие языки — позже, не решено.

Таб-бар (Главная · Избранное · Подать · Уведомления · Мои) виден только на `/`, `/favorites`, `/alerts`, `/my`. На остальных экранах — кнопка «Назад» Telegram и MainButton.

«Назад» (`src/navigation.ts`) ведёт на экран, с которого пришли, а не по истории браузера: табы начинают путь заново, в пути не больше одного объявления и одного профиля (нет цепочек «объявление → профиль → объявление…»), прямая ссылка ведёт на родительский раздел.

Основные сценарии:

1. **Найти рядом.** Главная → (сменить город/район в шапке) → категория или поиск → карточка → «Написать продавцу» → чат в Telegram.
2. **Подать объявление.** «Подать» → 5 шагов → «Опубликовать» → экран «Отправлено на проверку» → «Мои объявления». «Назад» на шаге возвращает к предыдущему шагу; с первого шага с несохранённым черновиком спрашивает подтверждение.
3. **Отложить.** Сердечко на карточке → вкладка «Избранное».
4. **Управлять своими.** «Мои» → поднять / архивировать / восстановить.
5. **Дождаться нужного.** Поиск «MacBook M2» в Бангкоке → «Ничего не нашли» → «Уведомить меня» → шторка уже заполнена (запрос, город, фильтры), можно уточнить категорию, район, цену, состояние → «Уведомить меня». Подписка появляется в «Уведомлениях» со статусом «ждём»; когда опубликуют подходящее, бот пришлёт сообщение, а в разделе появится «1 новое».

## Архитектура

```
Telegram-клиент
  └─ Mini App (этот репозиторий): React 19 + Vite + TypeScript
        └─ src/api  ──HTTP/JSON──▶  API: Python + FastAPI      (следующий этап)
                                      ├─ PostgreSQL — основное хранилище
                                      └─ Redis — обязателен (кэш, сессии, очереди/лимиты — детали не решены)
```

Фронтенд:

- **React 19**, **react-router-dom 7** (`BrowserRouter`), **lucide-react** (иконки).
- Состояние устройства — `src/store/app.tsx` (React Context + localStorage): выбранное место, избранное, тосты. В проде избранное и место будут синхронизироваться через API.
- Данные — только через `src/api`. Сейчас это мок с задержкой 350 мс поверх массивов из `src/mocks`; экраны уже обрабатывают состояния загрузки.
- Telegram — тонкая обёртка `src/telegram/telegram.ts`: вне Telegram все вызовы безопасно ничего не делают, а MainButton имитируется компонентом `MainAction`, кнопка «‹» в шапке `AppBar` показывается только в браузере — поэтому интерфейс можно смотреть в обычном браузере.

## Как открыть в Telegram

Telegram открывает Mini App только по **https**.

1. Запустите `npm run dev`.
2. Поднимите https-туннель на порт 5173, например `cloudflared tunnel --url http://localhost:5173` или `ngrok http 5173`. Vite может отклонить чужой хост — тогда добавьте его в `server.allowedHosts` в `vite.config.ts`.
3. В [@BotFather](https://t.me/BotFather): `/newbot` (если бота ещё нет) → `/mybots` → бот → **Bot Settings → Configure Mini App** (или **Menu Button**) → укажите https-адрес туннеля.
4. Откройте бота в Telegram и нажмите кнопку меню / Mini App.

Внутри Telegram браузерные «‹» и MainButton скрываются, работают нативные BackButton и MainButton. Пока бэкенда нет, `initData` никем не проверяется.

## Черновик API-контракта

Основа — сигнатуры `src/api/index.ts` и типы `src/types.ts`. Это **черновик** для FastAPI; пути и поля можно менять. Авторизация — заголовок `Authorization: tma <initData>`, сервер проверяет подпись `initData` токеном бота. Цены приходят в валюте объявления (`currency`) — это всегда валюта страны города объявления (`City.currency`). Фильтр по цене (`priceFrom`, `priceTo`) и `priceTo` в подписках — **в валюте выбранного города**, без пересчёта курсов: поиск всегда идёт в одном городе, значит, и в одной валюте.

| Метод фронта | HTTP | Ответ |
|---|---|---|
| `getListings(filters)` | `GET /listings?query&categoryId&cityId&priceFrom&priceTo&condition&withPhoto&delivery&sort` | `Listing[]` (только `active`; `sort=new` — сначала `promoted`) |
| `getListing(id)` | `GET /listings/{id}` | `{ listing: Listing, seller: User }`, 404 если нет |
| `getSimilar(listing)` | `GET /listings/{id}/similar` | `Listing[]` (до 6) |
| `getUser(id)` | `GET /users/{id}` | `{ user: User, listings: Listing[], reviews: Review[] }` |
| `getMyListings()` | `GET /me/listings` | `Listing[]` всех статусов |
| `getByIds(ids)` | `GET /listings?ids=a,b,c` (или `GET /me/favorites`) | `Listing[]` |
| `createListing(draft)` | `POST /listings` (`ListingDraft`) | `Listing` со `status: "moderation"` |
| `setStatus(id, status)` | `PATCH /listings/{id}` `{ status }` | `204` |
| `promote(id)` | `POST /listings/{id}/promote` | `204` (оплата — не решено) |
| `detectLocation()` | `GET /geo` | `{ cityId }` по IP запроса или `null` (не определили / город не обслуживаем) |
| `getKyc()` | `GET /me/kyc` | `'none' \| 'pending' \| 'verified'` |
| `startKyc()` | `POST /me/kyc` | запускает проверку в Didit, возвращает `pending` (детали — по документации Didit) |
| `getAlerts()` | `GET /me/alerts` | `AlertSummary[]` (подписка + `matches`, `fresh`) |
| `getAlert(id)` | `GET /me/alerts/{id}` | `{ alert: AlertSummary, listings: Listing[] }`; только чтение — совпадения новее `seenAt` фронт помечает «Новое» |
| `markAlertSeen(id)` | `POST /me/alerts/{id}/seen` | `204`; `seenAt = now` — фронт вызывает, когда человек уходит с просмотренного экрана подписки |
| `createAlert(draft)` | `POST /me/alerts` (`AlertDraft`) | `Alert` |
| `setAlertActive(id, active)` | `PATCH /me/alerts/{id}` `{ active }` | `204` |
| `deleteAlert(id)` | `DELETE /me/alerts/{id}` | `204` |

Совпадение (как в моке, `alertMatches`): объявление `active`, тот же город, район (если задан), категория, состояние, цена ≤ `priceTo` (в валюте города), **все слова** запроса есть в названии или описании, опубликовано после создания подписки. «Новые» — опубликованные после `seenAt`. Сервер должен проверять подписки в момент, когда объявление становится `active` (после модерации), и отправлять сообщение через бота. Как именно ставить это в очередь (Redis или иначе), частота и группировка сообщений — **не решено**.

Ещё понадобится, но во фронте пока нет: загрузка фото (`POST /uploads` → URL), синхронизация избранного (`PUT/DELETE /me/favorites/{id}`), справочники (`GET /categories`, `GET /cities`), жалобы (`POST /listings/{id}/reports`).

Ошибки — `{ "detail": "текст" }` (формат FastAPI по умолчанию); фронт показывает `detail` пользователю.
